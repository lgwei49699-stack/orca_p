### 建议的最小实施路线（尚未实现）

1. **先修已证实的独立错误。** 垫层扫描范围、首模型气隙判断、OBJ 同坐标顶点整理各自修复并回归；不通过放宽墙过滤掩盖这些问题。
2. **模板调整只按证据应用。** 短墙系数 2→0.5 可作为相关模板的候选基线，不能推广成所有模型都修复；脚掌的小区域过滤、经典墙首层宽度、精确外墙偏移要分别处理。0.3 mm 线宽和25%最小墙宽目前仅为归因对照，正式范围需设备/材料打印验证。
3. **为确实被过滤掉的有效区域做一次局部重生成。** 触发条件为切片轮廓非空、生成后该区域无有效挤出，且能定位到过滤阶段；保留原区域用于重试。短线阶段可评估 Cura 的外墙保护；面积阶段把数值噪声清理与可打印性判定分开，避免仅按原始宽线的面积阈值提前删掉本可由允许的较细线宽生成的区域。仅在校准允许的线宽、长度、挤出量及尺寸偏差内接受候选，不无限降阈值、不全模型反复切换配置。
4. **按区域检查恢复结果。** 要求挤出量为正、路径覆盖有效、首层有床面/支撑承托、相邻层承托连续，孔洞及外形偏差在允许范围。整体对象存在任意路径不能证明某个小岛或细节恢复；模型路径与支撑路径分别统计。
5. **保留真实空段的拒绝及明确原因。** 无几何截面或不能生成可打印路径时返回对象、Z区间和过滤原因，给出放大/改朝向/改喷嘴/补支撑的对应建议。可以另做用户明确选择的“允许损失底部细节”模式，但不把 Cura 的降落首层策略默认套到所有任务；中部空层不能压缩 Z。

可复用现有细节优化入口进行受控验证，避免增加一组重叠开关；现有 `optimize_model_detail_paths` 只处理特定短片段在简化中退化成重合点的情况，不覆盖全部过滤原因。首批验收包含脚掌、签名、魔鬼鱼、Watatsumi，以及真正几何空段、小孔和正常大模型；需比较细节路径、承托、尺寸和挤出，不能以退出码为唯一指标。正式实现涉及共享核心时需要 GUI/CLI 同配置对照，当前仅完成源码与方案分析。

## 面向成功率的商用最小方案（历史提案；任务重试已被用户否决）

### 决策与范围

首发采用“原参数切片 → 明确失败类型 → 一次单参数重试 → 验收后交付”。仅对审定的 EP3Plus、喷嘴/材料、工艺版本白名单和原有效 Arachne 短墙系数 2 生效，候选系数固定为 0.5；不是全量模板迁移。首轮成功保持原产物；首轮已经是 0.5/0、首末模型层丢失、几何空截面、模型过小、越界、碰撞、超时不进入此策略。多色、涂画/修改器、可变层高、自定义完整命令、修复联动等复杂入口先排除。

此前提出的按小岛重生成、外墙保留、小面积阈值改写属于下一阶段算法研发，不作为第一版商用的前置条件。确定性的垫层扫描范围/气隙判定修复及 OBJ 几何顶点处理独立发布与回归，避免一批提交同时改变参数策略和几何算法，失去归因能力。

157/389=40.4% 表示历史失败样本中的候选恢复覆盖率，不能声称总成功率提高 40.4 个百分点；单对象 116/389=29.8% 也只是覆盖上限，仍受白名单、配置身份和首末层排除影响。上线后的净成功率提升应为“新增通过且质量合格的任务数/全部提交任务数”，用对照组核对。156 条原重建对照、1 条本轮候选都没有完全等同生产二进制和最终参数，不能承诺线上恢复 157 条。

### 参数和失败识别的最小补齐

1. 引擎 `result.json` 现有 return_code 和 sliced_plates.warning_message 可复用，但 warning_message 是文字；增加稳定的失败子类型（如 empty_extrusion_layers）、对象/实际 Z 区间和实际生效参数摘要。首层异常也应结构化；字段缺失、未知版本、报告与输入/任务不匹配时不重试。普通 156 还包含其它切片异常，不能仅匹配整数或截断日志。
2. PDS `buildExecErrorMessage` 优先 stderr 且截断 2000 字符，普通切片未读取引擎结果 JSON，不能作为可靠自动分类依据。完整日志写尝试文件，失败判断读取本次报告；无需新诊断服务。
3. `getProcessSetting` 会合并模板、otherParams、层高/填充/垫层以及最后的显式墙参数；显式 Arachne 已整组覆盖 min_length_factor=0.5。`orcaSliceParam` 还会进入耗材设置，多对象存在独立 model-process。重试基于首次最终配置副本，只改变已确认来源的一个键，并由引擎回报最终值验证确实生效；不回查可能变化的模板、不通过外层 wallGenerator 触发整组覆盖。
4. 用户显式指定短墙系数、导入工程或覆盖来源无法判断时保持原意，不自动覆盖；先只接受来源明确的托管模板。157 条历史候选 params 中都没有 wallGenerator，otherParams 仅温度和部分支撑项，但这不证明未来所有请求都无手工覆盖。
5. 复用现有结果 JSON/工作目录保存原配置、候选配置差异、输入和引擎哈希、策略版本及两次结果。若不对外展示独立恢复字段，第一版无需改客户端接口和数据库表；持久日志/审计存储仍须保留，不能只靠会过期的临时目录。精确重放以实际参数快照为准，不能用“原请求+当时最新模板”重建候选。自动参数恢复单独配置策略，不重定义现有 optimizeModelDetailPaths 的显式算法开关语义。

### 验收与拒绝边界

- 原模型、位置、旋转、缩放、对象数量、层高、线宽/流量约束、支撑及垫层意图保持；参数差异严格限定 min_length_factor。首末层当前本来固定用 0.5，降低该系数不修复这些层。
- 必须由原失败区间的模型挤出路径恢复，不能只看到新支撑路径。可在失败摘要和候选验收中输出有几何的空模型层集合、有效模型路径长度/体积，确认原失败区间恢复且未增加新的空模型层；统计要递归处理实体，零长度或非正体积不算有效路径。该摘要只证明路径恢复，不是完整形状/实印证明。
- 保留原空层、越界、禁区、碰撞等检查；exit=0 且本次单盘产物有效才交付。绝不使用 no_check、删中间空层、整体降 Z、偷偷开启支撑或关闭垫层来提高统计成功率。
- 参数降低可能保留较短起停路径，增加耗时、拉丝或局部堆料；不等于改变最小允许墙宽。用适用机型/喷嘴/材料实印验证后才允许自动接受。不能用单个任意路径证明小岛细节全部恢复；局部完整性通过代表样本的路径覆盖/孔洞/尺寸/承托回归评估，若想对任意新模型给出这一保证，必须另做更完整的区域级算法。
- 经典墙第二策略只在已确认薄壁丢失、未显式禁用薄壁检测的白名单失败任务上设 detect_thin_wall=1，仍保留 classic，不附带多次换墙。加宽/开放单线的尺寸及强度影响需另行验收。

### 上线步骤与可回退性

1. 按实际生产 Linux 构建、最终参数和同一输入回放历史失败，按“模型文件+变换+生效配置”去重；包含全部 219 短墙记录、32 经典墙记录及已分清根因的 45 条反例。加入正常件、薄壁/小孔、装配件、噪声碎片、真正空段、首末层、不同支撑/垫层和多对象用例。失败集用于衡量恢复，正常集用于检测回归，分开统计。
2. 在同一新引擎上比较策略关闭/开启，首轮成功样本去除时间/路径等非确定性元数据后，运动与挤出指令应一致；引擎确定性 bug 修复另跑独立对照，不能要求被修复异常模型的路径保持不变。
3. 正式 Linux CLI 验证：报告类型/版本、参数最终值、缺报告/旧引擎拒绝、两次总超时、取消/进程回收、重复请求、尝试目录隔离、同任务单次终态通知、队列拥堵下不放大负载、产物上传失败处理；GUI 对共享核心的修复做同配置回归，服务恢复编排不新增 GUI 自动行为。
4. 代表性实印通过后，先只启用单对象、指定模板内容版本/喷嘴/材料；按失败任务 5%→20%→100% 灰度，再开放通过多对象覆盖测试的范围。比例是建议发布配置，不是已执行结果。
5. 观察恢复率、整批总成功率、队列等待 P95/总耗时 P95、CPU/RSS、重新切片率、实际打印失败及质量反馈。建议以 P95 等待或总延迟较对照恶化超过 10% 作为初始暂停阈值（需结合现网 SLA 校准），出现新增空层/越界/碰撞产物立即暂停。关闭策略回到原切片；引擎 bug 修复用独立镜像版本回退，不能假设同一策略开关能回滚 C++ 改动。

结论：第一版推荐有证据的失败后单次参数恢复，并独立修复确定性引擎错误。全量改模板、统一 factor=0、自动改变支撑/尺寸或大规模重写 Arachne 都不符合本轮“影响较小”的目标。当前交付为源码和保存证据的方案评审，尚未实现上述恢复能力，未进行新 Linux 集成验收或实机打印。


## 单次生成的路径保护（最新方案，尚未实现）

用户明确排除任务失败后修改参数并再切一次，关注性能与既有打印行为。建议改为引擎内“删除前判定 + 有下限的局部保留”，新增一个职责独立、默认关闭的运行时布尔开关（暂名 `protect_filtered_model_paths`，服务字段 `protectFilteredModelPaths`）；服务仍只调用一次 Orca，不自动改模板，不增加新的恢复队列/状态机。现有 `optimize_model_detail_paths` 同时控制拼接退化恢复和可变线宽转换修正，直接复用会把不同打印行为绑在一起，因此保留原语义，复用传递方式而不是混用同一开关。新能力尚不存在，不能只设置当前任何字段就声称完成；同一布尔值也需结合引擎版本记录具体算法身份。

### 过滤链与可控制位置

当前 `PerimeterGenerator::process_arachne` 按 Surface 处理，但简化/偏移后一个 Surface 可能分裂成多个 ExPolygon；`WallToolPaths::generate` 接收的也可能是多个连通轮廓。不能用整个调用的 toolpaths.empty() 代替独立区域消失检查，更不能因对象另一处有路径就忽略该区域。

### 首发短线保护的具体算法约束

1. 只在开关启用、明确来自模型墙、wall_loops>0 的适用入口执行。Arachne 还被填充调用，内部要区分用途，不能把所有 Fill/筏层/支撑调用顺带放宽。复杂修改器、多色、螺旋等未验证入口保持旧规则。
2. 复用已有生成/拼接后的候选，扫描时记录候选所属连通区域、旧规则的去留、正线宽/非零长度等。采用已有几何索引或局部包围盒筛选完成归属，避免路径与全部区域的笛卡尔积；无法可靠映射则保持旧结果。
3. 旧规则留下有效模型墙路径的区域保留原删除决定。只有旧规则会把一个独立区域的模型墙候选全部删掉时，保留该区域中符合下限的原候选。第一版下限采用现有半线宽过滤基线（0.5），不能自动降至 0 或降低 min_bead_width/min_feature_size。首末层本来用 0.5，不额外豁免。
4. 不是“随便捡最长一条让检查通过”：保留该区域通过准入的候选集合，并保持线宽/挤出计算、后续排序、碰撞与空层检查。局部有模型墙也不等于完整覆盖或存在真实承托；代表模型需核对区域覆盖和承托，未知场景不宣称物理打印已被证明。
5. 不调用第二次 `Print::process`、不重建整轮骨架、不下载或解析模型第二次、不重新生成其它区域。原候选和分类信息优先用索引/标记保存，不复制整套模型或每层全量路径。
6. 该方案按“墙区域完全丢失”触发，而墙生成阶段尚不掌握最终全部填充/支撑输出。因此不能宣称只改变原本必失败的任务：原本靠填充/支撑能通过但缺墙的区域也可能被保护。关闭必须保持旧行为；开启只承诺限定改变位置，新增路径可能影响排序、空走及最终打印时间，不能保证整份原 GCode 完全相同。

### 性能与商用验收

短线决策可把线宽/长度收集融合到原扫描，增加一遍局部分类或延迟删除；在区域归属已知时复杂度仍与路径点数量线性相关。若需几何归属查询，必须单独计量该部分，不能声称总算法严格线性或零成本。小区域延迟过滤会增加真正的 Voronoi/beading 工作量，噪声很多时可能显著变慢；经典薄壁中心线也有新几何计算，不能与短线保护混为同一性能承诺。

基准应分别测试开关关闭、开启但不命中、开启且命中，以及高噪声/大量碎片场景，固定输入、二进制和生效参数，多次测时间/峰值RSS并消除冷启动影响。可先以正常样本 P95 切片耗时增长不超过 5% 作为建议工程目标，尚非实测结果；复杂候选设置局部处理预算，耗尽时保持原过滤与失败语义，绝不跳过校验。关闭分支不创建保护缓存/执行新扫描，并以正常样本旧算法输出冻结对照。测试时既有 optimize_model_detail_paths 的值必须固定不变，只切换新保护开关，避免把原线宽计算差异算成此次保护副作用。

本轮不再沿用 157 条参数重试成功数推算新方案收益：全局改为 0.5 与“只保护即将消失的局部区域”不是同一算法，必须重新回放并逐个统计恢复区域和新增路径。首发先覆盖 219 条短墙记录的去重案例，并把脚掌小面积过滤、Watatsumi、精确外墙、真正几何空段和垫层异常作为不应误处理的反例。正常模型、小孔/装配件、噪声碎片用于限制影响；Linux CLI 与代表机型实印通过后再灰度。GUI 默认关闭的既有约定不自行改变，业务保护放共享核心，由调用方显式选择同一开关。

当前决策：同意用户提出的单次生成开关方向，以 Arachne 短线删除前局部保留为第一步；小区域、经典薄壁和偏移丢失分别验证后接入，避免“总开关取消全部过滤”。没有修改正式 C++/Java、模板或数据库，也没有运行新方案性能/模型回放，本文记录的是经源码核对的设计。


## 2026-10-29：进一步收敛到可验证的产品方案

用户继续询问更适合商用的方法。核心约束仍是一个默认关闭开关、一次切片，不自动重设参数或重切。更适合首发的实现基础是“按路径用途区分过滤”，参考已存在的上游规则，再以设备/材料验收限定适用范围；并不等于已有可以直接部署的已验证补丁。

已核对 CuraEngine 固定提交 `47b03886dc200b00f17fd40d7739a9da5a7b8745`：`removeSmallFillLines` 直接跳过 `line.is_outer_wall()`，其定义为 `inset_idx_ == 0`；其它 odd 开线仍按半线宽删除。本地 Orca 的 ExtrusionLine 同样保存 inset_idx/is_odd/is_closed，但 removeSmallLines 未作这一外墙豁免。只说明该过滤阶段的差异，不能推出 Cura 不会在前面的轮廓清理或后面的简化阶段丢失同一细节。保存源码与链接见前述 upstream 目录/来源。

首发候选范围：新开关只控制模型墙生成入口，在原短线删除条件命中时，区分具有外墙用途的有效候选与内部中心线；对已通过最小特征、有效线宽和设备实测路径下限的外墙/单线薄壁保留，内层短线保留原规则。路径角色是低成本第一层分类，不等于物理可打印证明；hole边界、最外层odd线、top单墙和同心填充的 inset_idx=0 语义必须逐项验证，不能只加一个裸 if(inset_idx==0) 就宣称商用完成。数值清理、最小特征和无效几何约束、实际空层和碰撞检查继续执行。无需先做全层面积布尔运算/跨层图谱来识别“是否全部丢空”，因此比依赖区域全空且需空间归属的方案容易限定成本。

明确取舍：按用途保护可以在模型主体仍有路径时保留短笔画，更接近细节完整性目标；它也可能改变原来能出GCode但缺细节的任务。开启时影响集合可能大于“整区全空”方案，不能承诺开启后所有旧成功模型不变。关闭保持旧行为；不命中短线删除条件的候选保持原过滤决定，新增候选仍可能影响后续全局排序。

不要把“被其它路径覆盖即可删除”作为首发通用规则：填充重叠不一定可代替外墙强度/表面职责，覆盖布尔运算和跨层连通证明还会增加性能与实现成本。仅内层短线的原过滤规则维持即可。需要扩大保护到 inset_idx>0 的内部关键连接时，必须证明角色、覆盖和承托，作为后续独立验证，不能从标签直接推断。

物理能力优先沿用有效配置的最小线宽/特征约束；新增最短可打印线段/挤出体积下限若采用，必须按指定机型、喷嘴、材料实测，不能把 0.5 倍线宽当作经过标定的硬件极限，也不能临时给全机型写死一个数值。一次切片中不动态改变这些值。来源不明的自定义参数、未标定配置先保持旧行为。

分阶段验收而不是叠加更多运行策略：先对 219 条短墙历史案例去重，比较原过滤、仅外墙保护、上一版整区保护三种本地实验结果（实验多组运行不等于线上重试）；同时测正常模型/小孔/装配/噪声、耗时和RSS。保留原空层拒绝，记录可打印路径恢复、尚缺失区域和新增路径。几何轮廓被提前删掉、经典墙没有候选、真正空段与垫层问题不计入该短线保护修复率。依据实印结果确定受支持的设备配置，再灰度同一个运行时开关。
