## 结案结论（2026-11-10）

任务 `1563633465107513344` 按模型底面几何归档，保留作回归样例。原姿态下，约 5,083 mm² 的水平底面高出最低凸尖约 0.344 mm。有机树在尖点附近生成小块承托，到人物宽底面处才生成大片支撑。新旧垫层模式均有这一现象。本例暂不调整共享支撑算法或空层检查。

## 直接证据与代码链

对象为 `f72176a98c5f.obj`（桌面交付文件 `XIANGRIKUI.obj`）。保持两个模型、变换和机器／耗材配置一致。

1. **模型首层无路径，关闭垫层靠支撑补足。** 无垫层、首层 0.32 的 GCode：Z=0.32 只有该对象的 Support 路径（106 条 XY 挤出运动），Z=0.52 才有模型 Overhang wall／Bridge。日志明确出现 `Tree support added a build-plate base for an unextrudable object first layer`。`TreeSupport3D.cpp` 的 `needs_first_layer_base` 要求几何首层有切片、周长和填充无覆盖，并且 `config.raft_layers.empty()`；对应支撑在 `organic_draw_branches` 后加入。开启垫层不满足该条件。因此关闭垫层能输出，并不证明首层模型细节已恢复。
2. **CuraV1 的树状支撑存在实际过大间隔。** 垫层顶为 1.32，气隙 0.25；有机支撑的 `TreeSupportSettings::raft_layers` 还包含到模型底 Z=1.57 的支撑层。0.32 配置下模型第一层计划 Z=1.89，但无挤出；Z=1.57 有 Support interface，第一段模型挤出在 Z=1.99。0.4 对应 Z=1.97 无挤出，首段模型挤出为 Z=2.07。前五层垫层均有实际路径，已排除上一轮偏心 ZigZag 漏填修复的同一故障。
3. **有机支撑按固定层数回退。** `TreeSupportCommon.hpp` 把顶部距离 0.2 / 普通层高 0.2 换算为 1 层；`TreeSupport3D.cpp::generate_initial_areas` 再加 1 层，以 `overhang_idx = support_layer_idx + 2` 选接触层。首个模型层厚度不同于普通层高，跨过该层回退两层并不保证实际间隙为 0.2。`layer_z()` 按首层高度加普通层高推算，也没有消费 `new_layers()` 对第二层及以后施加的 CuraV1 overlap。
4. **空层告警有真实间隔依据。** `GCode::collect_layers_to_print` 在当前模型层厚度 0.2、支撑顶部间隙 0.2 时，允许的下一挤出 Z 上限为 `1.57 + 0.2 + 0.2 = 1.97`。实际 1.99／2.07 均超过它。按该模型层厚度计算，支撑顶到模型挤出层底的间隙分别为 **0.22／0.30 mm**，大于配置的 0.2。不能把 `1.57～1.99` 的整个 0.42 mm 都称作纯空气：其中含模型层自身厚度。
5. **普通支撑对照通过。** 仅把 `support_type` 改为 `normal(auto)`，首层 0.32／0.4 都在未使用 `--no-check` 时退出 0。0.32 普通支撑在 Z=1.85667 仍有支撑界面路径，首段模型路径仍在 Z=1.99，说明本轮成功来自承托层安排变化，不是模型被改好。

`PrintObjectSlice.cpp::new_layers` 的本例高度：`1.32 + 0.25 + 首层高度 + 0.2 - 0.1`，得到第二模型层 Z=1.99／2.07。模型切面采样 Z 与打印抬升分别保存，开启垫层没有直接改变模型网格。

0.24／0.2 mm 两组均能导出。后续复核 0.24 mm 组时，大片支撑提前至 Z=1.32 mm 出现，下方仍缺少承托。

- 这里只分析一个真实任务及参数对照；尚未以全量测试证明所有树状支撑都存在同样问题。没有修复源码，未运行无关全量测试。
- 文档检查 `python3 scripts/check_ai_module_docs.py --all`：35 模块、问题 0；`git diff --check` 通过。构建 SHA256 复核未变，相关切层／支撑源码仍与 HEAD 一致。
- GUI 与 CLI 共用上述切层、支撑和 GCode 校验。GUI 待验：打开桌面的 `首层0.32_空层复现.3mf`，确认 CuraV1／首层 0.32／普通层 0.2；保持树状重切查看 1.57～1.99 告警；仅换普通支撑重切，检查模型开始前的支撑界面；再关闭垫层，检查 Z=0.32 为 Support 而非模型首层。CLI 通过不代替实机底面质量验证。

## 与 0.25 mm 调平薄片的区别

先前任务 `1563620823055826944` 的文件包含 0.10／0.25 mm 两片，模型首层原为 0.24 mm，气隙 0.22。0.25 mm 是几何厚度，不能当作首层配置。0.25 薄片当时有模型路径，报错来自偏心区域的 CuraV1 中间／顶部 ZigZag 缺失；该问题已由 `625b37a266` 修复，见[偏心垫层记录](2026-10-25-cura-raft-offset-fill.md)。0.10 薄片的漏采样另行区分。

本轮复用原右上角模型与有效配置，仅改模型首层，保留 `enable_support=0`、CuraV1 五层及气隙 0.22；同一当前应用正常校验：
