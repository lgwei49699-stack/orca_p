## 已确认并实现的方案：保留两阶段，删除多余处理

用户后续明确收紧：不为 App 修复新增尺寸提取、预览图生成或后台补图；是否产生修复结果直接使用现有 `repair.committed`，不另做“有效改动”判定。该设计已获授权，现已编码。

### 方案取舍

当前推荐保留服务已有 CHECK → 按需 ADVANCED 两阶段调用。检查完成就返回结果给 Slicer，服务根据现有 next_action 决定下一步，App 沿用当前状态字段。

前面提出的单进程内存复用能减少确需高级修复时的一次加载，但需要增加中途结果通知和日志流消费。对本次没有启动高级的 dragon，这项合并没有额外收益。考虑当前用户要求简单、少冗余，本轮不将它列为必须实现，不新增 stdout 中途协议、长驻进程或缓存。待两阶段精简后实测，只有“高级重新加载”仍为主要耗时才另评估。

### 执行流程

1. Slicer 下载一次原件到任务本地目录，保留原始 URL，不再上传原件快照。
2. 启动 basic 检查：读取本地模型、完成已确认的轻量检查，返回小型结果。取消 prepared 模型导出、回读、哈希绑定及阶段验收报告，检查不产生新远端模型。
3. Slicer 保存检查结果。`next_action=none` 直接使用原地址完成；`advanced_repair` 则先保存已有高级处理状态，再启动一次高级修复，读取同一本地文件，不再次下载。
4. 高级函数 `repair.committed=true` 才导出并上传最终结果一次；完整/部分成功沿用核心已有规则。未提交结果或修复失败保留原地址。不按字节哈希另判“改动是否有效”，不把所有残留缺陷都强制送入高级。
5. 主服务拿到终态直接完成，不再额外等下一次轮询，不在修复完成路径调用同步 ModelLoad。

```text
原地址 → 下载一次 → basic 检查 → 返回检查结果给 Slicer
                                ├─ 不需高级 → 返回原地址
                                └─ 需要高级 → 更新现有 App 状态
                                              → 高级读取本地文件并修复一次
                                              ├─ committed → 上传一次 → 返回新地址
                                              └─ 未提交/失败 → 返回原地址
```

两阶段确需修复时会再次读取本地文件，不承诺一次解析。它换取直接返回检查结果、保持现有阶段状态与超时处理；健康和 dragon 仍只启动一次引擎。

### 检查结果与 App 的区别

检查结果本身在 CHECK 命令退出时返回给 Slicer，保存在后端任务中；包括已测范围、缺陷和 next_action，不等待高级完成。App 现有查询接口返回 stage、repairAttempted 等状态，并不直接透传完整检查报告。最小方案不加新 App 字段：Slicer 需要高级时写 advanced/processing，主服务按既有逻辑映射 model_repairing；不需要时直接 model_ready。若用户以后明确要求 App 展示检测明细，再单独增加所需字段，不把它算成本轮已有功能。

普通模型不强制显示三步动画；实际修复时才显示修复；修复在两次查询间完成时不人为再等一轮。导入接口仍沿用轻量化期间返回 processing 的已有规则，不能把 handler 完成等同于页面立即跳转。修复未全部解决但可继续使用原件/部分成功结果时，内部保留 unresolved，不伪装全部修好。无法读取/空输入应明确处理失败，不无限转圈。

### 尺寸与预览的边界

本轮撤回先前“引擎顺带返回尺寸、后台补图”的扩展设计。主服务两类 handler 现有 fillModelMetadata 同步调用是已确认阻塞，拟从检测修复完成条件中移除。页面展示功能独立，不应为满足它而继续让修复转圈。

已有事实：导入请求支持 modelPreviewUrl，但当前 create 未保存该字段；当前模型尺寸/大小/缩略图由 ModelLoad 补入。故删除同步调用后，必须验证 App 对既有/缺失展示字段的实际行为，不能未经验证承诺所有展示数据仍与过去相同，也不能默默增加另一套后台工作。显示轻量化/大文件首帧问题单独记录，本轮不改打印模型为简化显示模型。

原地址本次位于 temp 目录，其生命周期没有核实；复用时核对既有文件管理的期限和再次打开/切片行为，不在检查步骤默认重传一份，也不承诺临时 URL 永久有效。

### 拟改范围与验证

- Orca：basic App 取消检查中间文件与重复验收；检查返回小型结果；高级仅提交结果才导出。普通切片/分盘、GUI/full、其他格式不进入该变化，不修改共享修复算法。

- 主服务：现有结果消费与状态映射；终态直接完成，移除同步 ModelLoad 阻塞。本轮不规划尺寸/预览的新生产者。
