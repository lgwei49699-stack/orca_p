# CLI 来源组顺序分盘

基准为 orca-slicer-soft 的 master，HEAD 为 `8d2ad2c559`，包含本工作区来源组改动。Mac arm64 Release 的实现与 CLI 验证已完成。该策略由 CLI 参数启用，本次功能验收使用 CLI。调用方接入时需传全局策略开关，并为已拆组件提供来源组号。

## 实现与构建

输入只导入一次。CLI 在每个模型块记录来源组并跟随对象合并，在实际排布前生成与组件一一对应的组号。试摆只处理当前候选的轮廓，保留材料、间距、床面、禁放区和擦料塔约束。同盘必须整组通过。候选失败继续试后面的组，首组单独也放不下时独占所需盘。擦料塔计划调整后的每次重排都重新执行同一策略。 [调用示例](../modules/cli.md) · [排布规则](../modules/arrangement.md)

本工作区原 arm64 缓存的 CGAL 是 5.6.3，无法配置当前 master。构建缓存改用本机已有的 CGAL 6.2.1 完整依赖前缀后，从本工作区源码重建 `cmake --build build/arm64 --config Release --target OrcaSlicer --parallel 8`。测试程序为 `build/arm64/src/Release/OrcaSlicer.app/Contents/MacOS/OrcaSlicer`，SHA-256 为 `259cde4378ff5c4cc63b8705c656126b3ec957e208bdbf0059363debdcf2f1da`。

## 实际 CLI 与回归

| 场景 | 验证结果 |
| --- | --- |
| 来源按列表首次出现，组件交错，编号不递增 | 10 个组件来自 5 组，3MF 实际成员按来源位置分为 1+3+5、2、4。JSON 的成员归属一致，3MF 内有三盘 G-code。 |
| 候选只有部分组件能加入 | 小组件随放不下的大组件一起留到下一盘，后续能完整放入的组进入首盘。 |
| 单组拆为多盘 | 一组的三个大件各占一盘，另一个来源从第四盘开始。 |
| 超尺寸／超高度成员 | 该来源的可排组件独占物理盘；超大件在 JSON 得到独立盘号、床面中心与 Z=0，保留输入的 37° 姿态。过高件也获得单独展示盘。 |
| 10 组合为一盘 | 日志只出现一次非空排布。与未启用新开关的同输入相比，各件盘号、XYZ、旋转和缩放一致。 |
| OBJ 与 STL 混用，双耗材 | 同来源同盘，3MF 的对象／部件耗材槽与普通模式对照相同，保留 1、2 两个槽。 |
| 启用擦料塔 | 实际出现逐盘预留与塔计划重排，两大件仍独占两盘，另一来源在第三盘。 |
| 参数与上限 | 拒绝缺失组号、零组号、未配开关、颜色／手动分组冲突、强制单盘、超过 10 个来源或需要第 37 个物理盘的请求。 |

`scripts/test_cli_source_group_arrange.py` 的 19 次 CLI 调用通过。原有 `test_cli_oversized_arrange.py` 184 次、`test_cli_fixed_position_slice.py` 64 个场景、`test_cli_model_color.py` 14 个场景均通过。简中目录通过 msgfmt 编译。构建与回归日志保存在本机临时目录 `/tmp/orca-source-groups-20261110`，其中 `final-source_group_arrange.log` 首行可定位实际的 JSON、3MF 及逐例命令。

## 性能对照

同一最终 arm64 Release CLI，100 × 100 mm 床，10 组共 20 个方块，间距 2 mm，忽略擦料塔。每种场景预热后交替运行普通模式和来源组模式各三次，取中位数。排布耗时为 CLI 日志的开始至结束；整条命令另含启动、读入和 JSON 导出。

| 场景 | 普通排布 | 来源组排布 | 整条 CLI 普通／来源组 | 来源组非空排布次数 |
| --- | ---: | ---: | ---: | ---: |
| 全部同盘 | 17.3 ms | 18.5 ms | 119.4 / 118.6 ms | 1 |
| 大小组交替，需跳组 | 24.7 ms | 84.5 ms | 128.5 / 185.5 ms | 21 |
| 每组独占一盘 | 10.1 ms | 37.1 ms | 112.2 / 139.6 ms | 56 |

实际耗时随零件轮廓、组件数量和擦料塔重排次数变化。上表未包含切片、后端网络、Linux 部署及实机打印耗时。

## 本地打包依赖复核

12:03 启动的 arm64 Release 发布构建在 12:05 编译 ColorUtils.cpp 时失败。上次 CLI 验证使用外部 CGAL 6.2.1 前缀，而发布脚本重新配置时指定仓库的依赖前缀，其中还装着 5.6.3。两个版本的 AABB 头在同一编译单元内重复定义模板。已按当前 master 固定的压缩包哈希重装本地 dep_CGAL，保留旧文件备份，将应用缓存统一为仓库内前缀并重新配置。原失败的 Release 对象已重编通过。该次验证覆盖配置和编译报错点，未执行完整打包。

来源组没有桌面 GUI 入口。CLI 测试已核对 JSON、3MF 和实际切片；本次没有进行 GUI 手测。
