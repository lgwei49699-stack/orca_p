| 一次请求过程中切换环境 | 已有完成回调检查，提示回原环境确认结果 | 增加登录恢复／导出后等过程检查，保留完成检查 | 保留环境检查，补写入前复核；区分“未发送”与“已发送”提示 |

具体例子：某工艺有 qa 来源记录，切到 production 后修改参数；650b 版本不显示保存按钮，当前未提交版本满足其他条件时显示按钮，但点击会因来源环境不同而提示，不执行保存。三档前没有来源环境信息，不会按该条件阻止，实际使用当前服务和原方案 ID，由接口返回结果。历史来源记录缺少 environment 时，650b 和当前代码都按读取时的当前环境兼容，不能宣称完整隔离所有旧记录。

源码依据：Plater.cpp 的 gfd_record_imported_cloud_config、gfd_get_active_imported_cloud_config、save_active_imported_cloud_config_async 和 start_gfd_config_upload_async。当前差异没有更改测试／线上域名，也没有切换环境自动复制或迁移本地预设。

另一个独立改动是删除“后台保存成功，但完成回调发现 token 不同就将 result.ok 改为 false”的分支。该分支在 72caa69f14（2026-08-27，ligw）已存在，不能称为仅撤回三档新增规则。原行为可能在 token 正常刷新或账号切换后显示“登录账号已切换”，且不会撤销服务端写入；当前未提交删除仅取消这次成功转失败的本地覆盖，接口鉴权仍在。本轮只解释，未继续删除／恢复其他 token 判断。

用户随后指出保存中无法操作其他界面，复核确认：GFDCloudConfigDialog::submit 禁用表单，cancel 在 busy 时不结束模态，关闭事件可否决时会被否决；finish 收到任务结果后才 EndModal，成功／失败均可结束。所以上段的环境／token例子只是分支语义，不能描述成正常手动操作可复现的问题。具体例外链路是 gfd_refresh_auth_token_for_worker → GFDAuthManager::ensure_logged_in_async；自动登录失败时可以弹出含环境选择的子登录框。但当前与 HEAD 的上传任务在 OBS、详情和保存接口恢复登录后均更新 task_result->request_auth_token，因此本任务正常恢复得到新凭证时，不会仅因初始凭证不同而命中旧完成检查。此前“正常刷新就会把成功改失败”的泛化解释不充分，需额外的会话变化证据；本轮未证明存在该并发问题，也未改代码。来源环境在打开保存前就已不同则是另一场景，不受保存中的模态锁定排除。

复核基准仍为 master/a08573a374 加现有工作区差异；本轮仅更新本记录，没有应用构建、GUI 操作或云端写入。

## 建议交互与实现边界

1. **加载行**：云导入复用本轮设备选择的底部固定状态行做法。进度条放列表下、取消按钮上方，隐藏时保留布局；状态区统一显示查询／下载解析／失败，避免覆盖列表和重复提示。此处当前是 wxScrolledWindow，不能据静态结构断言必然发生与设备选择完全相同的闪烁。保留 alive、generation、取消、登录重试与环境快照保护。
2. **上传配置**：明确目标方案和档位。新方案按新版规则先建立标准档；已有方案允许把当前配置补充到快速／精细，或覆盖已存在的指定档。不要自动把同一文件复制到三档伪造配置。若产品希望全新方案可单独上传快速／精细，先与后端确认放宽标准档必填规则。
3. **保存配置**：默认保存到导入来源方案及档位，确认框显示“方案名 · 档位”；显式变更目标档时告知覆盖对象。实现时读取详情并保留其他档位和方案备注，不能仅用 ID 与顶层文件更新整个方案。若后端提供单档更新接口应优先使用；整组更新还需明确并发修改处理方式。
4. **云端导入**：每个方案保持一个分组，标准／快速／精细分别显示标签、文件和导入动作；缺档显示“未上传”并禁用。导入某档后绑定 `方案 ID + fineness`，本地预设显示名也应区分档位，避免同名覆盖与保存串档。
5. **来源持久化**：GFDCloudConfigInfo、GFDCloudImportState 及 gfd_cloud_process_records 都需要保存档位。老记录可按兼容约定迁移为 standard，未知值不可默认为标准后写入。新增返回 ID 缺失时的列表回查也需按档位匹配文件，不能只查顶层 configFileUrl。
6. **实现入口**：MainFrame.cpp 的 GFDUploadConfigDialog、GFDCloudImportDialog、按钮绑定；Plater.hpp/.cpp 的解析、导入、上传及来源记录；GFDConfig 的 API 地址；中英文翻译。GUI 按钮目前走异步实现，文件中还保留同步封装，应共用协议转换逻辑避免两套行为漂移。

GUI／CLI 边界：在 src/OrcaSlicer.cpp 未找到对应云方案上传／保存／导入命令；本次是 GUI 云方案管理及服务协议适配，CLI 无相应业务入口。共享 3MF 参数导出／解析必须维持现有语义；不更改切片算法或按质量标签自动推导层高、速度。
