## 职责与边界

本模块负责GUI 生命周期与主工作台。归属以[模块清单](../modules.json)的 `gui-shell` 为准。

## 入口与调用

- [GUI_App.cpp](../../../src/slic3r/GUI/GUI_App.cpp)：on_init_inner/post_init；应用、配置、窗口与网络启动。
- [MainFrame.cpp](../../../src/slic3r/GUI/MainFrame.cpp)：主窗口页面、菜单与工作台生命周期。
- [Plater.cpp](../../../src/slic3r/GUI/Plater.cpp)：模型、侧栏、盘列表、切片和保存的 GUI 集成点。

## 核心流程

`GUI_App::on_init_inner()` 初始化配置、资源、窗口及网络基础设施，`post_init()` 继续加载。MainFrame 管理准备／预览／设备／项目页面，Plater 持有模型、侧栏、盘列表和后台切片状态；按钮由当前模型及任务状态决定可用性。

`Plater::export_gcode_3mf` 在开始时固定当前盘/全部盘目标，更新文件名所需背景状态后、保存文件框返回后分别验证目标盘切片和非空 G-code 文件；失效则要求重新切片，不回用旧缓存。共享 3MF 导出器再做核心约束，CLI 切片包遵循同一规则。普通工程保存不要求先切片。网格替换并落床后的首次刷新失效已定位到共享 Print 的部分区域缓存变换，按切片模块修正，不绕过 GUI 守卫；操作清单见[最新 GUI 交接](../validation/2026-10-05-reconstruction-gui.md#10-07-首次导出失效源头修正后验证当前待验)。

## 配置与约束

全部盘导出跳过没有可打印实例的模型盘，但保留没有可编辑实例且有切片/G-code 的导入盘；单盘仍严格校验所选盘。PartPlateList 提供共享盘状态，格式层同样筛选 G-code 与盘元数据，避免 GUI 放行后被禁用盘误拦截。不修改打印开关或替用户切换盘。

`send_gcode` 在 GUI 边界将 `PLATE_CURRENT_IDX` 解析为实际零基盘号，任务记录和 `export_3mf` 使用同一目标；共享导出器没有 GUI 当前盘上下文，不能直接传入 `-1`。明确盘号和 `PLATE_ALL_IDX` 不变，其他盘未切片不得阻止发送有效的当前盘。CLI 已使用明确盘号或全部盘，不新增“当前盘”状态；云配置完整工程导出不改。操作与待验项见[发送交接](../validation/2026-10-05-reconstruction-gui.md#10-07-传统当前盘发送目标修正)。

AppConfig 保存应用偏好，PresetBundle 保存当前工艺／设备／耗材选择；两者不可互相替代。设备品牌、语言、单实例及文件关联会改变启动分支。Plater.cpp 还是多个业务的集成文件，改动必须检查下游模块。

Advancer3 单次打印设置沿用设备选择窗口作为模态父窗口，查询和上传使用既有后台任务与存活／submission ID 守卫；调平和真实槽位只影响该机型，详见[云模块](cloud.md)。

## 失败与取消

MainFrame 在保存询问、reset 和 shutdown 之前调用 `veto_close_with_modal_dialog`：沿父窗口链检查仍处于模态的后代（含原生 wxDialog 和 Windows 自管模态），否决普通退出并提升最内层弹窗；先关闭弹窗再退出。否则菜单/Cmd+Q 可绕过禁用的主窗口，在 `ShowModal()` 尚未退栈时由 Plater 的 DestroyChildren 删除栈上设备选择框，引发非法 free。无模态时照常退出；不可否决的系统强制结束保留平台语义，未作为安全退栈保证。

启动失败、历史工程失效、预设警告和本次切片失败应分别记录。窗口销毁后不能继续使用异步回调中的裸 UI 指针；后台异常应通过主线程通知，不在工作线程操作控件。

## 修改与验证

改菜单、页面切换或启动时，验证首次启动、已有配置启动、打开项目和关闭取消；按[交接规范](../gui-validation.md) 输出并保存本次实际输入、操作顺序、预期和日志路径。两端都有的业务同时对照 CLI；纯窗口交互可说明 CLI 不适用。

现有测试/工具范围：`gfd_modal_dialog_tests` 覆盖原生／自管／嵌套模态下的主窗口关闭守卫及正常退栈后退出；完整应用菜单操作仍按本节检查场景验证。测试范围与实际通过记录分开，执行要求见[验证规范](../validation.md)。

云方案管理入口由 MainFrame 选择方案／档位，Plater 异步导出、上传、读详情合并与回读确认；导入列表三档按内容确定高度，表头固定，类型带边框标签；紧凑底栏保持加载条水平居中且不在加载时改变列表高度。取消／刷新使用灰色背景提示焦点；备注按实际列宽换行并更新行高，延迟布局合并尺寸事件且验证窗口存活。保存确认可选择配置类型并默认来源档位，旧来源默认标准；上传目标选择器每项单按钮、默认标准，保持正确的模态父窗口。上传表单区分新增和覆盖，入口按内容紧凑排列，“上传到已有方案”及辅助说明明确补充／替换类型；名称、备注可编辑且只传明确改动字段。上传表单“确定”完成本次提交确认，不再嵌套重复确认弹框。保存/上传表单提交后显示阶段进度，重登窗口归属于当前表单，保留旧任务凭证更新及完成检查；不按来源环境或本地账号绑定拦截保存，账号权限沿用接口认证与返回结果；文件上传百分比独立于服务端保存/回读。完成后先关闭原表单，再显示带方案和档位的成功结果；导入进入参数确认前停止底栏动画。来源持久化和实际云端及 Windows 视觉验收见[云模块](cloud.md)与[交接记录](../validation/2026-10-09-cloud-config-quality-analysis.md)。
