# 验证与证据规范

## 构建与测试责任

按 2026-10-04 的本项目长期约定执行，取代旧的“AI 不自行编译”限制；本规则不改变其他项目的验证偏好。

| 工作 | 负责与处理方式 |
| --- | --- |
| GUI／应用构建 | 用户通常执行；用户未构建且当前验证需要时，AI 补齐必要构建 |
| 测试目标构建 | AI 核查相关测试程序；缺失或过期则自行构建所需目标 |
| 自动化与 CLI 验证 | AI 执行、分析失败、修正后复测，保存命令和证据 |
| GUI 手测 | AI 输出并保存明确步骤，用户通常操作；AI 分析日志／产物并回填结果 |
| 已有可用构建 | 确认含当前修改后直接复用，不因新会话或换工具重复构建 |
| 纯文档／不依赖二进制的变更 | 运行文档／静态检查，不为形式完整而构建应用 |

缺少新构建时，AI 在任务所需范围内已获构建授权，无需重复确认。若用户明确说稍后由其构建或本次不构建，则先执行其他工作，记录等待项；不要与用户同时操作同一构建目录。工具链、依赖或目标平台确实不可用时，记录实际失败原因、已完成检查和剩余验证，不把构建阻碍掩饰成通过。

## 目标选择与程序身份

先核对分支／工作目录、源码与测试差异、资源版本、已有构建日志／配置和正在进行的构建，再选择最小目标。测试程序缺失时补测试目标；核心修改同时影响应用时，应用也须更新，不能只重建测试程序后让用户打开旧 GUI。GUI 单独改动需构建应用及相关目标；不默认全库、跨平台重编译或发布打包。

复用本分支现有 CMake 缓存和工具链设置。目标示例（先确认该构建目录及目标已配置）：

```sh
cmake --build build/arm64 --config Release --target OrcaSlicer --parallel 2
cmake --build build/arm64 --config Release --target libslic3r_tests fff_print_tests --parallel 2
```

按改动只选择相关目标；平台脚本是否同时打包、拷贝资源或安装依赖先读 [构建模块](modules/build.md) 对应入口。上面命令执行后必须核对实际退出码，不能只看 tee 成功或日志末尾。使用管道保存日志时保留构建命令的退出状态。

测试前核对构建日志、配置／资源及应用／测试程序哈希或对应内容身份；仅凭时间新或文件存在不足以证明包含本次修改。源码或测试再次变化时重新构建相关目标。macOS arm64 Release 多配置产物常见路径：

```text
build/arm64/src/Release/OrcaSlicer.app/Contents/MacOS/OrcaSlicer
build/arm64/OrcaSlicer/OrcaSlicer.app/Contents/MacOS/OrcaSlicer
build/arm64/tests/libslic3r/Release/libslic3r_tests.app/Contents/MacOS/libslic3r_tests
build/arm64/tests/fff_print/Release/fff_print_tests.app/Contents/MacOS/fff_print_tests
```

确认实际存在且与构建日志匹配。局部构建可能只更新链接产物，旧打包目录不会自动更新；交给用户的启动路径必须指向已核对的新应用及匹配资源。单配置／其他系统的路径不同，不跨工作目录或分支复用未经核对的程序。

## GUI／CLI 业务一致性验收

同步范围指同一分支提供的同一业务能力；不是要求窗口交互变成 CLI 参数，也不自动同步两条分支的历史功能。

1. 开始修改先列 GUI 入口、CLI 入口、共享实现和最终参数合成位置；已有端到端脚本／测试从相应模块定位。缺少某端接入时明确评估并补齐本次功能需要的入口。
2. 用同一输入、对象变换与盘归属、机器／耗材／工艺、对象覆盖及资源版本对照两端。比较有效配置，不只比较预设名称；GUI 自动修正／继承值与 CLI 显式值都要记录。
3. 共享核心业务优先由单元／集成测试覆盖；AI 再运行适用的 CLI 端到端场景，GUI 按 [交接规范](gui-validation.md) 操作。覆盖正常情况、与改动相关的边界／非法输入，以及涉及缓存时的重切、涉及事务时的取消／恢复。
4. 对照成功结果和拒绝／失败语义。分盘看盘数、归属、间距及边界；路径看模型／筏层挤出与空移，比较坐标、实际线宽、厚度、挤出量及必要顺序；保存看重开后的配置／对象状态。GUI 弹窗、CLI 退出码／JSON、产物内容分别记录，出现矛盾需定位。
5. 时间戳、缩略图和日志等表示差异可以单独排除，但必须说明；树状支撑等已知非确定性需要选择合理的几何／业务判据，不能要求所有文件逐字节相同，也不能为通过而临时放宽断言。仅总耗时或总重量相近不证明路径一致。
6. 纯 GUI 文案或只在一端存在的管理操作可以标记另一端不适用，写明入口与理由；不能把缺验证写成“不适用”。需要 GUI 验证而尚未执行时，状态保留“待 GUI 验证”，继续完成不依赖它的工作，不宣称全部验收。

已有差异要区分本次新增与历史问题，并记录影响和后续处理；用户明确暂缓的事项保留，不借本规则扩大任务或静默抹去问题。

## 专项入口

- 修复：既有过滤器 `'[ModelRepair],[MeshBoolean],[SavedPainting],[OBJ],[stl]'`；检查分支实际标签/目标。核心、导入、保色和事务回退同时核对，不能只跑健康方块。
- 筏层：`'[SupportMaterial][Raft]'`；分盘：`'[Arrange][Raft]'` 仅对存在这些用例的分支适用。共享筏层可让一个接收对象没有本地路径，但整组每层应有效；多次树状生成不保证逐点顺序一致。
- 路径：按模型挤出、筏层挤出、空移分别比较坐标、实际宽度/厚度/挤出量及顺序。物理 Z、盘原点、轮廓和料线半宽不能混用。跨缝和实机可靠性保留模型师验证。
- 预设：测试入口见模块清单。首次安装、旧配置升级、用户覆盖、坏项隔离与 GUI 向导应分别验收，不把清空缓存后的成功当升级正确。
- 文档：仅 Python 标准库工具测试，不会编译切片程序；纯文档变更不需要切片业务构建或 GUI 操作。
