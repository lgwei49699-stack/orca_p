# 代码图可用性与降级

本文件与根 AGENTS 的 CodeGraph 规则配合，目的是避免把每次新会话/新工作目录都当成需要初始化。

| 现象 | 判定与处理 |
| --- | --- |
| 当前工具列表没有 codegraph MCP | 只说明会话未暴露；查看项目配置和已安装 CLI，不能据此断言没有索引 |
| command -v 无结果 | CLI 可能不在 PATH；核对配置指定的可执行路径，不主动下载安装 |
| 当前目录没有 .codegraph | 用本分支模块 MD 和源码继续；不复制其他 worktree 数据库，不自动 init |
| status 显示最新但缺文件/哈希不同 | 索引过期或覆盖不足；先 sync，复查目标文件，不依赖单一状态文字 |
| CLI/DB 读取失败 | 保留错误与降级来源；继续文档/源码，不循环初始化 |
| 切分支、来源不明 | 检查仓库/分支/HEAD、目标文件与内容身份，不把另一分支索引当事实 |

## 本轮实际核查

原工作目录已有 CodeGraph v0.9.6 CLI（项目 MCP 配置指定路径）；当前会话没有 MCP，CLI 不在默认 PATH。原 status 的 3,394 文件“最新”提示不足以证明当前分支覆盖：抽查 PrintConfig 哈希失配，GuideMachineMetadata/RaftMerge 缺失。

按授权只对原工作目录的既有索引执行一次增量 sync，输出新增 39、修改 121、删除 2，共 162 项。随后三项均存在且 SHA256 与当前源码一致；没有执行 init 或全量 index。进一步核对 src 下 1,135 个 .cpp/.hpp/.c/.h/.mm 文件，全部存在且 SHA256 匹配；当前索引总计 3,427 个文件。完整审计边界见 [验收记录](validation-report.md)，不能把抽查通过表述为全部动态调用已覆盖。

文档整理时两处临时 worktree 均未创建索引；随后按用户要求将文档直接放入 master 和 master_v_user。master 复用原目录索引，master_v_user 工作目录仍通过模块文档与源码定位，不共享可写 DB。检查脚本只调用 Git，Python 临时仓库测试覆盖无 CodeGraph 的正常工作，任何检查参数均不会重建图谱。

## 使用顺序

确认 Git 状态 → 读任务相关模块入口 → 使用已确认新鲜的结构查询 → 对缺失/过期部分读源码 → 检查差异/验证身份。已有图谱同步失败时明确说明限制，不阻断业务。Understand-Anything 的历史图谱也只能作导航；没有任务需要就不重新生成。

常用结构入口：context/explore 看上下文，trace 追调用链，callers/callees/impact 查依赖；具体子命令以本机 CLI help 为准（v0.9.6 提供 query 查询符号）。同一次任务已确认新鲜的结果可复用，文档变动本身不要求同步源码索引。
