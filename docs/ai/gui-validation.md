# GUI 验证交接与记录

本文件规定需要 GUI 验证时 AI 应交付什么。构建／自动化分工和 GUI／CLI 对照判据见 [验证规范](validation.md)；不是每项修改都执行一次完整 GUI 回归。

## 何时需要 GUI

涉及参数控件、菜单／按钮、选择范围、预设加载、后台状态／取消、预览渲染、保存重开等交互时，必须列出对应场景。核心业务同时供 GUI／CLI 使用时，还要确认 GUI 传入的有效参数与新结果实际生效，不能只用单元测试替代入口验证。纯文档及与 GUI 无关的工具改动写明无需 GUI 的原因即可。

## AI 交付清单

每次交接在回复中列出本次具体步骤，并链接已保存的验证 MD；不要只写“你再试一下”或只有模板。普通修改优先覆盖最关键的正常、边界、状态恢复场景，按风险补充，不重复无关场景。

- **构建身份**：分支、工作目录、源码／资源身份、应用准确启动路径、构建完成情况；测试使用的程序与用户打开的程序是否相同。必要的启动／日志命令应填完整可用路径。
- **复现输入**：实际项目／模型路径和身份、对象数量／尺寸／变换／盘数；使用现有工程还是新建工程。提供可获得的测试输入，不能让用户猜测合成模型怎么搭建。
- **有效配置**：机型、喷嘴、平台、耗材、工艺；全局／对象覆盖、开关与数值、界面语言。只改一个变量的对照明确前后值。
- **逐步操作**：所在页签和参数名称、选择哪个对象／盘、具体点击及顺序；特别注明重新切片、保存后重开、切换对象或取消的触发时机。
- **每步预期**：应看到的数值、路径／状态、允许的提示及不应出现的错误；有量化边界就写出来，不能只写“正常”。
- **回传证据**：本次日志路径与时间段、导出的项目／G-code.3mf 等实际文件、必要截图。已有日志可直接读取；只有确实缺失的信息才再向用户索取。
- **对应 CLI 验证**：同参命令／脚本和输出目录、AI 已核查的结果；标明 GUI 尚需验证的项目。真实打印质量与软件路径检查分别记录。

默认由用户完成交互手测；AI 完成自动化、CLI、日志和文件复核。如任务适合且用户授权的范围允许 AI 操作 GUI，应保留相同证据，不拿静态截图冒充操作全程。

## 保存位置与模板

优先更新该功能已有的 `doc/` 专题进度／验收 MD；没有专题时使用 `docs/ai/validation/<日期>-<功能>.md`。后者是按需新增的活动记录，不要为每次对话制造空文件。受影响模块的“修改与验证”链接到该记录。

一份记录可有多轮复测：保留旧失败与对应身份，新增本轮结论。原始日志和导出大文件留在忽略的 planning 目录或用户指定目录，MD 只记录定位与摘要；不要把临时绝对路径当作其他开发者必然可用的仓库资源。

以下模板须按本次改动填写后交付，不把未执行字段填成通过：

```markdown
# 功能验证记录

## 改动与身份

说明本次目标、分支、源码／资源身份、应用路径、构建日志和测试目标。

## 两端接入

说明 GUI 操作入口、CLI 命令／脚本、共用实现、有效参数来源及允许的表示差异。

## 输入与准备

列出实际模型／项目、参数和初始状态；需要恢复初始状态时给出方法。

## GUI 操作清单

| 场景 | 具体操作顺序 | 预期结果 | 对应 CLI 证据 | GUI 实际结果／状态 |
| --- | --- | --- | --- | --- |
每个实际场景单独一行，说明动作、参数和观察点；待用户操作时明确写待验证。

## 自动化与 CLI 结果

记录命令、身份、用例／断言数、退出码、输出文件，以及失败定位和复测轮次。

## 用户回传与复核

记录操作时间段、日志／文件路径、截图能证明什么，以及尚不能确认的部分。

## 当前结论

分别列自动化、CLI、GUI 状态，剩余问题／不适用理由；不要将未执行项计入通过。
```

## 场景选择

| 改动 | 通常需要的 GUI 观察 | 两端对照重点 |
| --- | --- | --- |
| 参数、预设 | 字段单位／中英文、恢复默认、对象覆盖、保存重开 | 实际配置键和值、继承、合法零值、默认值 |
| 分盘 | 单／多对象、固定对象与边界、取消后位置 | 盘数、归属、变换、间距、拒绝原因 |
| 支撑／筏层／路径 | 本分支支持的模式切换、重切、首层及相关层预览 | 层 Z、角色、边界、路径连续性、普通支撑保持 |
| 模型修复／文件 | 选择对象、颜色／绘制保留、失败恢复、导出重开 | 修复选项、几何／属性、事务和实际产物 |
| 纯界面显示 | 高 DPI、主题、窗口切换、错误提示 | CLI 无界面操作可不适用；共享导出／解析仍需检查 |

## 收到结果之后

先核对用户操作的应用和配置身份，定位本次时间段，再结合导出文件判断。写清“日志显示完成”“文件验证通过”“用户确认界面符合预期”各自证据范围；过期日志、缺文件或只有截图时明确限制。修正后更新相关构建及受影响场景，不无依据重复全部测试；最终回复和 MD 的结论保持一致。
