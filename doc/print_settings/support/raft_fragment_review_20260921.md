## 3. 当前代码可以确定的问题边界

当前流程是：阶段轮廓合并 → 平滑／开运算 → 阶段预内缩 → 切缝差集 → 平台求交 → Orca 支撑墙／填充生成 → 按线宽裁剪 → 候选覆盖检查。

1. `Support/RaftGeometry.cpp` 在**切缝前**已有开运算清理。切缝差集仍能产生新的窄片，所以不能表述为“完全没有轮廓清理”，也不能认为增大平滑就必然解决分块后的碎片。
2. `Support/RaftMerge.cpp::generate_shared_paths()` 复用 `fill_expolygons_with_sheath_generate_paths()`。它采用固定线宽的支撑墙／填充流程；基底先画四圈墙，然后最后按分块区域和床面裁剪，并非 Cura 的完整墙路径生成流程。
3. `SupportCommon.cpp::clip_raft_collection()` 按“半线宽 +0.001 mm”构造中心线安全范围。裁剪后的线仅须有两个点且长度大于 `SCALED_EPSILON`，即 **0.0001 mm**，因此 0.015 mm 残段会保留。这是数值有效性判断，不是打印质量过滤。裁剪可能将连续墙拆成短段，是需要优先核对的生成／裁剪衔接位置。
4. `omitted_fragments=4` 只表示：四个候选轮廓与已生成料线完全无交集，被从输出元数据省略。只要还有一小段挤出，轮廓就会保留。它**不是四个残留碎片，也不是完整的小岛清理统计**。

本轮试图用只读 LLDB 抓取同一恢复项目的裁剪前后路径，两次均在调试器启动阶段超时，没有获得捕获结果；相关诊断进程已结束。不能宣称已经逐条证明全部超短线由末端裁剪产生。以上实存短线由用户本次真实 G-code 直接证明；裁剪阈值及处理顺序由源码证明。局部形状问题与数值裁剪问题须分别修正。

## 6. 下一步收敛方案

建议作为一项局部的“分块后轮廓与路径生成衔接”修正处理，而非继续放宽误差：

1. 先固定当前龙项目的分块轮廓和实际输出，补入切缝交汇、孔边、尖角的碎段验收；确认墙的生成内缩与最终中心线裁剪采用一致边界，避免原可连续的墙在最后被重新切碎。裁剪前后完整归因仍须补证。
2. 借鉴上游按物理线宽／最小可打印特征整理轮廓和路径的流程。每个分块内部处理，结果仍限制在该块原允许区；不把闭运算跨块执行以填回 0.8 mm 切缝，不改模型几何。
3. 对残片区分轮廓、可打印路径及其用途，保留正常短填充与有效小模型承托。避免全盘固定面积硬删，也不把整个 Arachne／Cura 墙生成器直接移植进这次局部修正。
4. 延续已核实的 Xmaker 分块规则及上一轮明确的参数来源修正；平台、禁打区、混摆检查独立保留。模型首层流量、气隙、分盘策略不在此项修改范围。
5. 用户新构建后重跑专项及真实龙项目，比较连续路径、短段、小岛、切缝、线宽包络和耗时；100/180 mm 平台、带孔、窄条、小模型、多对象合并都需要覆盖，再进行实物剥离对照。

不建议仅开启更大的平滑值就判为解决，也不建议把所有长度小于 1 mm 的路径删掉。准确范围仍需裁剪前后证据收敛，当前不能承诺一个常量改动就消除全部碎片。
