## 2026-09-22 用户收敛范围后的业务结论

本节覆盖此前的候选优化建议。用户明确暂不处理 CLI 分盘结果协议、擦料塔、筏层上模型首层独立流量、复制实例／铺满热床及复杂逐对象差异设置。本次只复核源码与既有证据、更新分析，不修改生产代码，不新增产品提示。

### 同组对象的分块设置不同

当前按相互重叠的筏层占地建立连通组，并非整盘所有对象一组。`RaftMerge.cpp` 的 `same_geometry_options()` 要求分块开关和平滑量一致；分块开启时，还要求参考尺寸及缝宽一致。不一致时，`apply_raft_geometry()` 跳过该组的分块和平滑，继续保留原有合并结果；不修改对象保存的参数，也不直接取消其他组的增强。

例如 A 开分块、B 关分块且两者筏层相连：A／B 仍可共享原筏层，但该组不切缝；即使两者平滑量相同，当前也一起跳过平滑。把 B 移到独立组后，A 才能按自身参数处理。对应既有回归为 `Different geometry settings retain the existing shared raft instead of restoring duplicates`。

业务影响主要是这类少见设置组合中，开启的效果未应用；现有证据未显示因此漏模型、重复输出共享筏层或改动模型本体。常用全局统一参数不受该不一致判断影响。

| 方案 | 效果与代价 | 当前建议 |
|---|---|---|
| 保留当前一致性要求 | 行为简单，保持现有合并与回归基线；代价是分块差异也会取消同组平滑 | 推荐，符合用户暂不做逐对象差异设置的范围 |
| 分块和平滑分别协调 | 分块设置不兼容则整组不分块；平滑量全部一致时仍可平滑，反向同理；需补有效组合、几何门禁及重切恢复验证 | 可选的小到中等改动，当前不实施 |
| 强选一个对象的设置，或只对组内部分对象切缝 | 前者可能违背明确关闭的设置；后者需定义共享区域归属、保护范围和过渡 | 当前不采用 |

## P1-B：连续操作与恢复

每组选择代表模型执行 10–20 轮操作，覆盖：

1. 开关分块／平滑，调整参考尺寸、缝宽和平滑量，再恢复原值。
2. 移动或删除共享筏层的一个对象；关闭其中一个对象的筏层，分别验证冲突拦截和移开后成功。
3. 在普通、有机树与混合树间切换；校验简化步骤重新执行，旧支撑／筏层来源标记不残留。
4. 保存／重开 3MF，以及现有切片缓存往返；来源信息不全时遵循既有回退，不能把普通支撑误认成筏层。

普通支撑保留应比较同次生成前后的实体、坐标、物理 Z、流量和归属；树支撑不同次生成可能有差异，不能要求独立重切 G-code 字节一致。共享筏层只输出一次，关闭增强后正确恢复原始路径，非法结果不可导出。

## P1-C：真正运行中的取消

在筏层规划、支撑占地处理、路径重建／校验及候选提交前触发取消，记录从请求到停止的时间。已有“开始前即取消”的测试保留，但不替代这里的响应测量。

检查取消后无部分候选提交、无被误标为可导出的半成品；再次切片能够成功，结果满足与正常切片相同的几何及输出归属约束。仅在实测发现长时间不可取消时，才补循环中的检查点，避免在几何事务提交到一半时中断。

## P2：测量后再决定的优化

若路径生成／覆盖校验在多个代表场景中持续占主要耗时，先确认现有包围盒筛选是否有效、同一轮是否有重复布尔运算，再考虑局部复用或减少重复复制。新增缓存应限定生命周期并有明确失效条件，不先引入跨对象的长期复杂缓存。

任何生产或测试 C++ 修改都需要用户重新编译相应目标。之后运行 `[SupportMaterial][Raft]` 及缺陷聚焦回归，用同一套性能夹具比较；不放宽平台、物理 Z、线宽、混摆冲突或取消门禁换取速度。

## 记录与完成条件

每轮证据保存在独立 `planning/raft/` 目录，记录 checkout、源码与二进制哈希、平台配置、命令、日志、结果 JSON、G-code 检查、耗时和退出码，摘要同步到 `raft_geometry_trial_progress.md`。

用户负责构建与剩余 GUI 操作，AI 按长期授权运行匹配构建的已有测试和无编译 CLI 脚本。发现缺陷先复现、限定范围并修复，等待新构建再验证；不借用旧测试证明新源码。完成条件是 P1 代表矩阵通过、异常有明确处理且无未关闭的软件阻塞项，未测范围如实保留。

## 固定验证入口

用户编译新增测试后，先运行 `'[SupportMaterial][Raft][Geometry][Stability]' --reporter compact`，再运行完整 `'[SupportMaterial][Raft]' --reporter compact`。新增聚焦测试已经包含在完整过滤器中。用户构建命令为：

```bash
cmake --build build/arm64 --config Release --target fff_print_tests --parallel 2
```

CLI 采集器和工具自身测试不触发构建：

```bash
python3 scripts/test_raft_stability_helpers.py -v
python3 scripts/validate_raft_stability.py \
  build/arm64/OrcaSlicer/OrcaSlicer.app/Contents/MacOS/OrcaSlicer \
  --output planning/raft/stability-新目录
```

`--output` 必须是新目录，默认每场景 3 次；可用 `--list` 或重复 `--case` 缩小范围。`--profiles` 指向已解析的机器／工艺／耗材 JSON 根目录。夹具覆盖值、实际配置、输入哈希、逐次命令、日志、JSON、G-code 和耗时均保留；不修改用户预设、不自动摆盘、不发往打印机。

采集器退出码：0 表示所选检查通过；1 表示输出、边界或配置等检查失败；2 表示存在明确回退需要复核。场景名 `off` 只关闭分块／平滑，筏层仍然开启。独立 CLI 超时终止只用于防止采集卡住，不能当作应用内部取消验证。当前边界解析仅支持矩形平台与矩形禁打区。
