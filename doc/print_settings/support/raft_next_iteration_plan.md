# 筏层下一轮：稳定性与性能验证计划

更新：2026-09-22。上一轮已提交 `ddbd608dd9`（带支撑的筏层分块／平滑、路径来源隔离、重切失效和树支撑计时）。本页是下一轮计划，不表示以下测试已经执行，也不默认启动新的几何改造。

## 当前基线与目标

- macOS arm64 / Release，完整筏层专项 79 用例／32,665 断言通过；带支撑聚焦测试包含在其中。
- 用户最新混合树 GUI 切片完成，分块生效且普通支撑保留。该任务是 AD5X 220 mm 平台、0.25 mm 喷嘴、平滑为 0，不代表 EP3／EP7 实际配置已经验收。
- 同次测量：树支撑生成约 1.26 秒，筏层几何约 1.17 秒，其中路径生成与校验约 1.12 秒；单次数据只能帮助选择测量位置，不能证明普遍性能瓶颈。
- 已有测试包含合成 100／180 mm 平台、三次重放、缓存和预取消恢复；尚缺大量对象、连续操作及运行中取消响应的实测。
- 打印剥离效果、小支撑脚跨缝强度由模型师验证。软件验收重点是路径来源、输出归属、几何边界、状态恢复和耗时。

## 优先级及执行顺序

| 顺序 | 工作 | 目的与交付 | 改动范围 |
|---|---|---|---|
| P1-A | 100／180 平台与多对象基线 | 记录有效参数、对象／实例数、各阶段时间、峰值内存、输出规模和回退原因 | 优先使用已有 CLI、日志及测试，必要时增加不触发构建的验收脚本 |
| P1-B | 连续重切和缓存恢复 | 验证开关、参数、移动／删除、保存重开后的状态不残留 | 有明确缺口再补确定性测试；发现缺陷才改生产代码 |
| P1-C | 运行中取消 | 证明取消不会留下半成品路径，且后续切片可正常完成 | 若现有入口不足，增加测试中的取消注入；不增加产品参数 |
| P2 | 针对测量结果做性能优化 | 只优化能够稳定复现的慢阶段，并比较修改前后耗时和路径语义 | 小范围处理重复几何计算，保留全部安全门禁 |

P1 是补齐软件证据，目前没有证据认定一定存在新的速度或取消缺陷。预计先用 1–2 个工作日完成基线和操作验证；若需补运行中取消测试入口，另预留约 1 个工作日。性能修复是否需要及工作量在测量后确定，不能提前把它当作必做改造。

## P1-A：有限、可复现的验证矩阵

使用解析后的 EP3 100×100×100 与 EP7 180×180×180 机器／耗材／工艺配置，记录文件哈希及实际 G-code 参数。按模型尺寸选择可放入的平台，排不下的场景单列为拒绝测试，不混入性能比较。

| 维度 | 代表场景 |
|---|---|
| 模型形状 | 大平底、龙形环状底面、桌腿等小接触区域、带悬空的支撑模型 |
| 对象规模 | 1／10／25 个独立对象；180 平台补可容纳的 50 个小对象 |
| 筏层增强 | 全关作为基线、仅分块、仅平滑、两者开启 |
| 支撑类型 | 无支撑、普通 Grid、有机树、混合树；Snug／Slim／Strong 沿用已有专项，按差异补代表场景 |
| 混摆 | 全部开筏层；筏层与关闭筏层对象／Brim／支撑混摆；手动冲突负例 |

不做所有维度的笛卡尔积：先固定小样本覆盖行为，再把稳定配置扩大对象数。大量对象基线使用当前支持的单实例对象；复制实例场景单独记录既有跳过行为，不能将其当作合并已经支持。

对相同输入与配置顺序运行至少 3 次，区分新进程完整切片和同进程重切，记录中位数、范围与环境负载。比较总切片、支撑、筏层规划、支撑占地、路径生成／校验时间及峰值内存；不以打印时间估算切片速度。

验收重点：结果有限且无异常、平台外无非法料线、共享筏层无重复输出、混摆冲突仍被阻止；记录大模型/对象数增长趋势。首轮不承诺统一毫秒阈值，异常增长必须复现并定位后才能称为性能问题。

## P1-B：连续操作与恢复

每组选择代表模型执行 10–20 轮操作，覆盖：

1. 开关分块／平滑，调整参考尺寸、缝宽和平滑量，再恢复原值。
2. 移动或删除共享筏层的一个对象；关闭其中一个对象的筏层，分别验证冲突拦截和移开后成功。
3. 在普通、有机树与混合树间切换；校验简化步骤重新执行，旧支撑／筏层来源标记不残留。
4. 保存／重开 3MF，以及现有切片缓存往返；来源信息不全时遵循既有回退，不能把普通支撑误认成筏层。

普通支撑保留应比较同次生成前后的实体、坐标、物理 Z、流量和归属；树支撑不同次生成可能有差异，不能要求独立重切 G-code 字节一致。共享筏层只输出一次，关闭增强后正确恢复原始路径，非法结果不可导出。

## P1-C：真正运行中的取消

在筏层规划、支撑占地处理、路径重建／校验及候选提交前触发取消，记录从请求到停止的时间。已有“开始前即取消”的测试保留，但不替代这里的响应测量。

检查取消后无部分候选提交、无被误标为可导出的半成品；再次切片能够成功，结果满足与正常切片相同的几何及输出归属约束。仅在实测发现长时间不可取消时，才补循环中的检查点，避免在几何事务提交到一半时中断。

## P2：测量后再决定的优化

若路径生成／覆盖校验在多个代表场景中持续占主要耗时，先确认现有包围盒筛选是否有效、同一轮是否有重复布尔运算，再考虑局部复用或减少重复复制。新增缓存应限定生命周期并有明确失效条件，不先引入跨对象的长期复杂缓存。

任何生产或测试 C++ 修改都需要用户重新编译相应目标。之后运行 `[SupportMaterial][Raft]` 及缺陷聚焦回归，用同一套性能夹具比较；不放宽平台、物理 Z、线宽、混摆冲突或取消门禁换取速度。

## 暂缓与独立事项

- 多实例展开合并、全分支独立筏层生成器、跨对象强制统一工艺参数：维持当前范围，待真实使用需求推动。
- 筏层上模型首层流量、自动调整跨缝承托和 Xmaker 式整体轮廓替换：本轮不列入软件稳定性工作。
- CLI 自动分盘未排入却可能返回 0／产生空模型 G-code，是已有的独立结果协议缺口（见 `support_settings_raft.md` 的 2026-09-22 分盘验证记录）。应在服务端依赖 CLI 结果上线前单独修复并验收，不能算作筏层分块算法的问题或已解决项。

## 记录与完成条件

每轮证据保存在独立 `planning/raft/` 目录，记录 checkout、源码与二进制哈希、平台配置、命令、日志、结果 JSON、G-code 检查、耗时和退出码，摘要同步到 `raft_geometry_trial_progress.md`。

用户负责构建与剩余 GUI 操作，AI 按长期授权运行匹配构建的已有测试和无编译 CLI 脚本。发现缺陷先复现、限定范围并修复，等待新构建再验证；不借用旧测试证明新源码。完成条件是 P1 代表矩阵通过、异常有明确处理且无未关闭的软件阻塞项，未测范围如实保留。
