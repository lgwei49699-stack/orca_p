## 要解决的问题

原分盘为每个对象保留完整筏层外扩。例如两侧各预留 5 mm 时，模型间距至少约
10 mm。切片已能合并兼容筏层，继续用该间距会浪费平台空间，也使自动排列后的
筏层不容易相接。此轮让确认兼容的对象按模型间距排列，实际筏层仍在切片阶段合并。

## 首版范围与规则

| 场景 | 本轮行为 |
|---|---|
| 矩形平台、逐层打印、至少两个参数一致的 CuraV1 独立对象 | 启用紧凑候选排列；固定对象可以参与兼容判断 |
| 自动间距 | 两个模型轮廓各预留 1 mm，即模型间距至少约 2 mm；不是两片筏层之间留 2 mm |
| 显式设置间距 | 使用指定的模型间距；平台装不下时继续分到其他盘，不为了合并强制缩小间距 |
| 筏层与筏层 | 允许外扩区域重叠；实际相接才合并，间隙仍保留，不强制连成一整片 |
| 热床边缘 | 模型必须在既有收缩后的平台内；筏层外扩沿用切片裁剪。现有单对象空盘居中补放继续可用 |
| 禁放区／固定虚拟障碍 | 仍保留完整筏层包络和原障碍间距，并对候选进行复查 |
| 真实固定对象 | 原位置不动；已确认兼容时只要求模型间距，允许共享筏层 |
| 按颜色或手工分组分盘 | 保留原 `arrange_group`，不同硬分组仍不得同盘 |
| 开关筏层混摆、支撑开启、逐对象打印、多实例、铺满热床 | 不启用本轮紧凑优化，继续原规则 |
| 配置不同、多耗材、擦料塔、可变层高、修改器／手绘支撑、非矩形平台 | 继续原规则；本轮不扩大兼容范围 |

“参数一致”使用有效 `PrintObjectConfig` 的完整比较，另要求同一活动耗材、支撑耗材
没有切换到其他工具、有效筏层层数与阶段计划一致。自动值与显式值即使解析结果
相同，也可能因配置不同而不启用紧凑排列。这是本版保守边界，不会修改用户保存的
对象参数。没有新增 GUI／CLI 开关，不调整分块 40 mm、缝宽 0.8 mm、平滑 0 mm
等默认值，界面的“试用”文案也不在本轮修改。

## 实现与失败处理

- `ModelArrange.cpp`：在常规 GUI／CLI 分盘入口统一检查参与对象，记录独立的
  筏层障碍预留。保留原 `inflation`／`minimum_inflation` 供原流程使用。
- `Arrange.cpp`：仅矩形平台对临时副本进行紧凑排列，模型间距使用较小预留，
  禁放区反向增加被移除的筏层预留。不修改 libnest2d 内核。
- 排列后检查模型床内／高度、对象间距、固定对象和禁放区。完整候选通过后仅复制
  位置、角度、盘号和顺序；候选未完成或校验失败则以原参数执行原分盘流程。
- 取消在候选提交前保留调用方原位置，不通过 `on_packed` 发布中间候选。
  含障碍时关闭候选的整体末尾对齐，避免移动对象相对固定区域的坐标关系。
- GUI 的 `ArrangeJob` 及 CLI 普通／assemble 分盘均接入；`FillBedJob` 不接入。
  后续擦料塔重试若加入塔对象，会禁止紧凑候选并保留原预留。

禁放区使用保守的切片前占地估计，包含普通接触网格增长、最大筏层线宽的一半及
0.05 mm 余量；它与模型之间的 2 mm 间距是两种约束。新候选被拒绝时可能多跑一次
原分盘，尚无本轮耗时数据，不宣称提速。切片合并算法、混摆实际冲突校验及导出
门禁沿用现有代码，本轮不放宽。

诊断日志为 `[arrange-diag] compact_raft`，记录通过兼容判断的数量、完整障碍预留、
实际采用的模型间距，以及 `placement_not_complete`、`obstacle_clearance`、
`model_clearance` 或 `fixed_model_clearance` 候选拒绝原因。
